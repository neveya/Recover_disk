# Disk Recover Tool (Developed by Claude.AI)

NTFS · FAT12/16/32 · exFAT 디스크 이미지와 드라이브에서 **파일 목록(폴더 구조 포함)을 읽고, 삭제되었거나 손상된 파일을 다른 디스크로 복사(복구)**하는 읽기 전용 도구입니다.

> **⚠️ 먼저 읽어 주세요**
> - 이 프로그램은 **무료로, 있는 그대로(AS IS), 어떠한 보증도 없이** 제공됩니다. 사용으로 생기는 모든 문제(데이터 손실 포함)의 책임은 사용자에게 있습니다. 자세한 내용은 [DISCLAIMER.md](DISCLAIMER.md)와 [LICENSE](LICENSE)를 보세요.
> - **복구한 파일은 반드시 '다른 디스크'에 저장하세요.** 복구하려는 드라이브에 쓰면 삭제된 데이터가 영구히 덮어쓰입니다.
> - 중요한 데이터이거나 디스크에서 소리가 나거나 인식이 불안정하다면, **사용을 멈추고 전문 복구 업체에 문의하세요.** 불량 디스크를 계속 읽으면 상태가 더 나빠질 수 있습니다.
> - 본인 소유이거나 접근 권한이 있는 저장장치에만 사용하세요.

## 1. 주요 기능

- 디스크 이미지(`.dd` `.img` `.raw` `.001` 분할 이미지, E01은 선택 설치 필요) 또는 **드라이브/물리 디스크를 읽기 전용으로** 열어 파일·폴더 목록 출력
- 삭제된 파일과 폴더도 목록에 표시
- 파일마다 **정상 / 의심 / 손상추정** 판정(메타데이터 검사, 선택적으로 파일 앞부분 시그니처 확인)
- 폴더 단위로 골라서 **원래 폴더 구조 그대로 복사**, 복사 진행률(경과/예상 시간, 용량, %) 표시, 결과 보고서(CSV) 저장
- `--root` 로 **특정 경로 아래만** 목록·확인·복구
- 손상이 심한 NTFS(`$MFT` 일부 소실 등)를 위한 스캔 모드, 루트 폴더가 손상된 FAT 의 유실 폴더 탐색

## 2. 지원 범위와 한계

| 항목 | 지원 |
|---|---|
| 파일시스템 | NTFS, FAT12/16/32, exFAT |
| 입력 | raw 이미지, 분할 이미지(.001), E01(선택), 드라이브(`E:`), 물리 디스크(`\\.\PhysicalDriveN`), Linux 블록 장치 |
| 운영체제 | Windows 10/11 (주 대상), Linux (`sudo`). macOS는 미지원/미검증 |
| 파티션 | MBR, GPT(백업 헤더 포함). 표가 없으면 부트섹터를 직접 탐색 |

**지원하지 않거나 한계가 있는 것**

- **암호화된 볼륨**: BitLocker 등으로 암호화된 상태의 디스크를 물리 디스크로 읽으면 암호문이 읽혀 복구할 수 없습니다. 잠금이 풀린 상태의 드라이브 문자(`C:`)로 열거나, 복구 키로 잠금을 푼 뒤 사용하세요.
- NTFS **압축 파일**, **EFS 암호화 파일**은 복사하지 않습니다(목록에는 표시).
- ext4, APFS, HFS+, ReFS 등 다른 파일시스템은 지원하지 않습니다.
- **SSD**는 삭제 직후 TRIM으로 내용이 지워지는 경우가 많아, 목록에는 있어도 내용이 비어 있을 수 있습니다.
- **FAT/exFAT에서 삭제된 파일**은 클러스터 연결 정보가 지워지므로 "연속 저장"을 가정해 복구합니다. 조각났던 파일은 내용이 어긋날 수 있어 **의심**으로 표시됩니다.
- 복구 가능성은 삭제 후 해당 드라이브에 쓰기가 얼마나 있었는지에 크게 좌우됩니다. **복구를 보장하지 않습니다.**

## 4. 설치

### 방법 A. 실행 파일(exe) — Python 불필요

1. [릴리스 페이지]에서 `DiskRecover-버전.zip` 을 내려받습니다. 내려받은 파일의 SHA-256 해시가 릴리스 페이지에 적힌 값과 같은지 확인하세요.
2. **복구할 드라이브가 아닌 곳**(USB 등)에 압축을 풉니다.
3. 드라이브/물리 디스크를 읽으려면 `DiskRecover.exe` 를 **관리자 권한으로 실행**합니다.

> 일부 백신이 PyInstaller로 만든 exe를 오진할 수 있습니다. 걱정되면 아래 방법 B(소스 실행)를 쓰거나, 소스를 직접 확인한 뒤 직접 빌드하세요.

### 방법 B. 소스 코드 실행

1. Python 3.10 이상을 설치합니다 (https://www.python.org/downloads/ — 설치 화면에서 *Add python.exe to PATH* 체크).
2. 버전을 확인합니다.
   ```
   py -3 --version
   ```
3. `disk_recover_tool.py` 를 내려받아 **복구할 드라이브가 아닌 곳**에 둡니다.
4. 실행해 봅니다.
   ```
   py -3 disk_recover_tool.py --help
   ```
5. (선택) E01 이미지를 읽을 때만:
   ```
   py -3 -m pip install libewf-python
   ```

### 방법 C. 직접 빌드 (개발자용)

```
py -3 -m pip install pyinstaller
py -3 -m PyInstaller --onedir --uac-admin --name DiskRecover disk_recover_tool.py
```

- `--onedir` 를 권장합니다. `--onefile` 은 실행할 때 C: 의 임시 폴더에 압축을 풀기 때문에, **C: 드라이브를 복구하는 상황에서는 삭제된 데이터를 덮어쓸 수 있습니다.**
- `--uac-admin` 은 실행할 때 관리자 권한을 요청합니다. `--noconsole` 은 쓰지 마세요(콘솔 프로그램입니다).
- 결과물은 `dist\DiskRecover\` 폴더입니다. 폴더째 압축해 배포하세요.

## 5. 복구 전 안전 수칙

1. **지금 당장 해당 드라이브 사용을 멈추세요.** 새로 저장되는 모든 파일이 삭제된 데이터를 덮어쓸 수 있습니다.
2. **복구한 파일은 다른 디스크에 저장**하세요. (도구는 읽고 있는 디스크와 같은 디스크에 저장하려 하면 막습니다.)
3. 이 프로그램도 **복구할 드라이브가 아닌 곳(USB 등)에서 실행**하세요. 설치/내려받기도 해당 드라이브에 하지 마세요.
4. 가능하면 **디스크 전체를 이미지로 먼저 만들고**(FTK Imager 등) 이미지로 작업하세요.
5. 가능하면 해당 디스크를 **오프라인**(Windows 디스크 관리) 또는 읽기 전용으로 바꾼 뒤 읽으세요.
6. 시스템 드라이브(C:)는 사용 중에 계속 쓰기가 발생합니다. 가능하면 다른 PC에 연결하거나 부팅 USB / Windows 복구 환경에서 작업하세요.
7. 불량 징후(이상한 소리, 느려짐, 인식 끊김)가 있으면 읽기를 멈추고 전문 업체에 문의하세요.

## 6. 사용법

### 6-1. 가장 간단한 방법 — `--browse`

```
py -3 disk_recover_tool.py E: --browse
py -3 disk_recover_tool.py D:\backup\disk.001 --browse
py -3 disk_recover_tool.py \\.\PhysicalDrive1 --partition 1 --browse
```

대화형 화면에서 폴더를 이동하고 선택한 뒤 `copy` 를 입력하면 저장 경로를 묻고 복사합니다. 복사가 끝나면 목록으로 돌아와 이어서 다른 폴더를 복구할 수 있습니다.

| 명령 | 설명 |
|---|---|
| `ls [쪽]` | 현재 폴더 목록 |
| `cd N` / `cd ..` / `cd /` | 폴더 이동 |
| `s N [N..]` / `s .` / `s all` | 선택 (`s .` 은 현재 폴더 전체) |
| `u N` / `u all` | 선택 해제 |
| `sel` | 선택 목록 보기 |
| `find 글자` | 이름·경로 검색 (결과는 `s r3` 처럼 선택) |
| `bad` | 이 폴더 아래 손상추정 파일 보기 |
| `x 경로` | 선택에서 제외할 경로 추가 |
| `clear` | 선택·제외 모두 비우기 |
| `copy` | 복사 시작 |
| `q` | 종료 |

### 6-2. 명령으로 한 번에

```
# 연결된 디스크/볼륨 확인 (관리자 권한)
py -3 disk_recover_tool.py --list-drives

# 폴더 구조와 손상 현황 요약
py -3 disk_recover_tool.py E: --tree

# 특정 폴더만 복구
py -3 disk_recover_tool.py E: --select /Documents/보고서 --copy-to F:\복구

# 특정 경로 아래만 빠르게 보고 복구
py -3 disk_recover_tool.py E: --root /Users/홍길동/Documents --check-data --browse

# 손상이 심한 NTFS 이미지 (오래 걸림, 결과를 저장해 재사용)
py -3 disk_recover_tool.py disk.001 --mode scan --cache scan.pkl
```

### 6-3. 배치 파일(선택)

`복구도구.bat` 같은 배치 파일을 함께 배포하는 경우, 실행하면 참조할 대상(드라이브 문자, 물리 디스크 번호, 이미지 경로)을 물어본 뒤 `--browse` 모드로 시작합니다. `L` 을 입력하면 디스크 목록을 보여 줍니다.

## 7. 옵션 설명

### 대상 지정

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `image` (첫 인자) | 이미지 파일 또는 장치 (`E:`, `\\.\PhysicalDriveN`, `/dev/sdb`) | - |
| `--drive N` | `\\.\PhysicalDriveN` 을 대신 지정 | - |
| `--list-drives` | 연결된 디스크·볼륨 목록 출력 후 종료 | - |
| `--partition N` | 볼륨 후보가 여럿일 때 사용할 번호 (생략하면 물어봄) | - |
| `--offset 바이트` / `--size 바이트` | 볼륨 시작 위치/크기를 직접 지정 | - |

### 읽기 방식

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--mode auto\|mft\|scan` | NTFS: `$MFT` 우선 읽기 / `$MFT` 만 / 전체 스캔(오래 걸림). FAT: `scan` 은 루트에서 이어지지 않는 폴더 탐색 | `auto` |
| `--cache 파일` | 스캔 결과 저장·재사용 | - |
| `--scan-range 시작:끝` | 스캔 범위(GiB) | 전체 |
| `--no-probe` | 선언된 `$MFT` 끝 뒤 영역 탐사 생략 | - |
| `--gen current\|old\|all` | NTFS: 현재 세대 / 이전 세대(MFT 연장 구간) / 전부 | `current` |
| `--check-data` | 파일 앞부분을 읽어 확장자 시그니처와 대조(느림) | 끔 |
| `--oem-cp 코드` | FAT 짧은 이름(8.3) 문자 코드. 일본어는 `cp932` | `cp949` |
| `--root 경로` | 이 경로 아래만 목록·내용확인·복구 대상으로 삼음. `--copy-to` 와 함께 쓰고 `--select` 를 생략하면 그 경로 전체를 복사, `--browse` 는 그 폴더에서 시작 | 전체 |

> `--root` 참고: FAT/exFAT 는 해당 폴더만 읽어서 빨라집니다. NTFS 는 경로를 복원하려고 `$MFT` 전체를 읽어야 하므로 목록 읽기 자체는 빨라지지 않고, `--check-data` 와 복사 범위가 줄어듭니다. 범위 밖 파일과의 클러스터 공유(교차 연결) 검사는 제한됩니다. 경로는 대소문자를 구분하지 않으며, 폴더가 삭제되었거나 상위 폴더가 손상됐다면 `[유실된폴더_번호]` 아래에 있을 수 있으니 `--browse` 의 `find` 로 찾으세요.

### 목록 표시와 필터

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--head N` | 콘솔에 보여 줄 목록 개수 (`0` = 전체) | `30` |
| `--all` | 시스템 메타파일($MFT 등)도 표시 | - |
| `--deleted-only` | 삭제된 항목만 | - |
| `--only-issues` | 의심·손상추정 항목만 | - |
| `--csv 경로` / `--no-csv` | 결과 CSV 저장 경로 / 저장 안 함 | `ntfs_list_result.csv` |
| `--tree [깊이]` | 폴더 트리 요약(생략 시 깊이 2) | - |
| `--no-color` | 색상 끄기 | - |

> 장치(드라이브/물리 디스크)를 읽을 때는 결과 CSV를 자동 저장하지 않습니다. 저장하려면 `--csv` 로 **다른 디스크의 경로**를 직접 지정하세요.

### 복구(복사)

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--browse` | 대화형 탐색기로 선택·복사 | - |
| `--copy-to 폴더` | 선택한 항목을 이 폴더에 원래 구조로 복사 | - |
| `--select 경로` | 복구할 폴더/파일 (여러 번 지정 가능, `/` = 전체) | - |
| `--select-file 파일` | 복구할 경로 목록 파일 (한 줄에 하나, `#` 주석) | - |
| `--exclude 경로` | 선택에서 제외 | - |
| `--skip-deleted` / `--skip-damaged` | 삭제된 항목 / 손상추정 파일 제외 | - |
| `--no-tag` | 손상추정 파일명에 `[손상추정]` 을 붙이지 않음 | 붙임 |
| `--overwrite` | 같은 이름이 있으면 덮어씀 (기본: 같은 크기면 건너뛰고, 다르면 번호를 붙여 저장) | - |
| `--force` | 저장 공간 부족 경고 무시 | - |
| `--report 경로` | 복사 보고서 CSV 경로 (`_folders.csv` 가 함께 저장됨) | 저장 폴더 옆 `ntfs_copy_report.csv` |

## 8. 결과 읽는 법

**건강도**

| 표시 | 의미 |
|---|---|
| 정상 | 검사한 항목에서 특이사항 없음 (**내용이 온전하다는 보증은 아닙니다**) |
| 의심 (노랑) | 확신할 수 없음. 예: 삭제된 FAT 파일을 연속 저장으로 가정해 복구 |
| 손상추정 (빨강) | 연결이 끊김, 클러스터 덮어쓰임, 교차 연결, 시그니처 불일치 등 |

- 손상추정 파일은 복사할 때 파일명에 `[손상추정]` 이 붙습니다. 손상추정 파일이 든 폴더는 복사 결과 요약에 노랑으로 표시됩니다.
- 판정은 **추정**입니다. 손상추정이어도 열리는 파일이 있고, 정상이어도 깨진 파일이 있을 수 있습니다. 복구 후 직접 열어 확인하세요.

**목록 맨 앞 표시**: `D` 폴더 / `x` 삭제 / `o` 이전 세대 레코드(NTFS) / `i` MFT 레코드 없이 인덱스에서만 복원(복사 불가) / `s` 스캔에서만 발견(NTFS)

**보고서(CSV)**: 원래 경로, 저장 경로, 복사 결과, 최종 판정, 삭제 여부, 기록된 크기, 복사된 크기, 시그니처, 번호, 메모. 색상이 보이지 않는 환경에서도 이 파일로 구분할 수 있습니다.

## 9. 상황별 안내

**삭제한 파일 복구 (NTFS)**
`--tree` 로 폴더를 찾고 `--browse` 또는 `--select` 로 복구합니다. 삭제된 항목은 `x` 로 표시되고, 클러스터가 다른 파일에 재사용됐다면 손상추정이 됩니다.

**NTFS가 인식되지 않거나 폴더가 대부분 `[유실된폴더_번호]` 로 나올 때**
`--mode scan --cache scan.pkl` 로 한 번 스캔하세요(디스크 용량에 따라 매우 오래 걸립니다). 이후에는 `--cache scan.pkl` 만 주면 재사용합니다. 캐시 파일은 **다른 디스크**에 저장하세요. 캐시는 Python pickle 형식이므로, **출처를 모르는 사람이 준 `.pkl` 파일은 열지 마세요**(악성 코드가 실행될 수 있습니다).

**FAT 루트 폴더가 손상됐을 때**
`--mode scan` 으로 디스크에서 폴더 구조를 직접 찾습니다. 찾은 폴더는 `[유실된폴더_클러스터번호]` 아래에 묶입니다(exFAT/FAT12 제외).

**C: 드라이브 / BitLocker**
- 물리 디스크(`PhysicalDrive0`)가 아니라 **볼륨 `C:`** 로 여세요(잠금이 풀린 상태에서는 평문이 읽힙니다).
- 가능하면 Windows 복구 환경이나 부팅 USB에서 BitLocker 복구 키로 잠금을 푼 뒤 작업하세요(실행 중에는 C:에 계속 쓰기가 발생합니다).
- 프로그램은 USB에서 실행하고 결과도 USB/외장 디스크에 저장하세요.
- 먼저 휴지통, 파일 탐색기의 "이전 버전", OneDrive 버전 기록을 확인하세요.

**읽는 도중 디스크에 쓰기가 일어나면**
복구 대상 데이터가 덮어쓰일 수 있고, 목록·파일 위치가 서로 다른 시점의 값이 섞일 수 있습니다. 읽는 동안에는 해당 디스크에 쓰지 마세요.

## 11. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `접근 거부 - 관리자 권한이 필요합니다` | 관리자 권한으로 실행한 콘솔/exe 에서 다시 실행 |

## Python 이 설치되지 않은 PC에서 사용하기 (exe 빌드)

복구 대상 PC에 Python 이 없으면, 다른 PC에서 exe 로 빌드한 폴더를 USB 로 가져가 실행합니다.

1. 빌드용 PC(Python 3.10 이상)에서 `build.bat` 실행 → `dist\DiskRecover\` 폴더 생성
   (또는 GitHub Actions 의 `build-windows-exe` 워크플로가 만든 `DiskRecover-win64.zip` 사용)
2. **폴더 전체**를 USB 에 복사 (`DiskRecover.exe` 단독 복사 불가)
3. 복구 대상 PC에서 `DiskRecover.exe` 더블클릭 → 관리자 권한 허용 → 시작 메뉴에서 드라이브/디스크/이미지 입력
4. 복구 결과는 반드시 **다른 디스크**(USB 등)에 저장

주의
- `--onefile` 로 빌드하지 마세요. 실행 시 C: 임시 폴더에 풀려 삭제된 데이터를 덮어쓸 수 있습니다.
- 서명되지 않은 exe 는 백신/SmartScreen 이 경고(오탐)할 수 있습니다. 소스 공개로 검증 가능합니다.
- 창이 바로 닫히는 경우: 관리자 cmd 에서 `DiskRecover.exe` 를 직접 실행하면 오류 문구를 볼 수 있습니다.

## 탐색기 화면(`--browse`) 명령 요약

`--browse`(또는 시작 메뉴)로 열면 `/폴더> ` 프롬프트가 나오는 대화형 폴더 탐색기가 뜹니다.

| 명령 | 설명 |
|---|---|
| `ls [쪽]`, `cd N`·`cd ..`·`cd /` | 목록 보기 / 폴더 이동 |
| `s N`·`s .`·`s all`, `u N` | 선택 / 선택 해제 (`s r3`, `s r1-r20` 은 검색 결과 번호) |
| `find [-h] [-a] 글자` | 이름·경로 검색 (`-h` 이 폴더 아래만, `-a` 쪽 나눔 없이 전부) |
| `ll [-a]`, `bad [-a]` | 이 폴더 아래 전체 파일 / 손상추정 파일을 폴더별로 |
| `recent [일수] [-a]` | 삭제된 파일을 삭제 추정 시각(NTFS는 MFT 변경 시각) 역순으로. FAT/exFAT은 수정 시각 기준 |
| `usn [일수] [-a] [-h] [글자]` | NTFS 변경 저널(`$UsnJrnl`)의 삭제·휴지통 이동 이벤트(최신순). 복구 후보가 있으면 `-> r번호` 표시 |
| `x 경로`, `clear`, `sel` | 제외 / 선택 비우기 / 선택 목록 |
| `copy`, `q` | 복사 시작(저장 위치를 목록에서 선택) / 종료 |

`usn` 참고: 저널은 오래된 기록이 순환하며 지워지고, 꺼져 있거나 이미 덮어쓰였을 수 있습니다. 이벤트가 있어도 파일 내용이 살아 있다는 뜻은 아닙니다.
